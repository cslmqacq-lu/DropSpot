# DropSpot 最小化与悬浮窗分离设计

## 目标

将主窗口的系统最小化与 DropSpot 悬浮窗拆分为两个独立行为，避免“点击最小化却出现悬浮窗”的语义混淆。

## 交互设计

- 点击 Windows 标题栏最小化按钮时，主窗口正常最小化到任务栏，不显示 mini 悬浮窗、收藏展开栏或钉住文件夹。
- 顶部黑色工具栏增加一个图标按钮，提示文字为“打开悬浮窗”。点击后隐藏主窗口并显示现有 mini 悬浮窗及钉住文件夹。
- 悬浮窗右键菜单中的“恢复主窗口”继续恢复主窗口原来的位置和最大化状态。
- 悬浮窗右键菜单在“恢复主窗口”之后增加“最小化到任务栏”。点击后关闭所有悬浮界面，并让主窗口进入真正的 Windows 任务栏最小化状态。
- 由悬浮窗执行“最小化到任务栏”后，用户点击任务栏恢复时默认重新进入悬浮窗，不显示主窗口；由主窗口标题栏执行最小化时仍恢复主窗口。
- 使用 `--startup` 开机启动时继续直接进入悬浮窗模式，不在任务栏留下最小化主窗口。

## 资源与状态

- 文件监视在真正最小化和悬浮窗模式下都继续运行。
- 真正最小化时暂停主窗口卡片和收藏列表重绘，只更新内存数据；从任务栏恢复后一次性刷新当前视图。
- 悬浮窗模式继续只维护悬浮窗口内容与钉住文件夹，不改变现有收藏、路径复制、双击打开和拖动行为。

## 异常与边界

- 重复点击“打开悬浮窗”不会创建重复窗口。
- 从悬浮窗执行“最小化到任务栏”时，监视继续运行，收藏展开栏、提示框和钉住文件夹必须全部隐藏。
- 程序记录本次最小化是否来自悬浮窗，并在 Windows 处理任务栏恢复前拦截该来源的 `SC_RESTORE`，防止主窗口闪现。
- 外部再次启动 DropSpot 时，单实例激活仍恢复主窗口。
- 明确执行“恢复主窗口”或收到单实例激活时必须清除“返回悬浮窗”标记。
- 窗口位置只在主窗口可见且非最小化时记录，防止最小化坐标覆盖正常恢复位置。

## 验证

- Release 编译必须为 0 错误。
- 完整冒烟测试必须通过。
- 手动验证标题栏最小化留在任务栏，顶部按钮进入悬浮模式，两个入口行为互不混用。

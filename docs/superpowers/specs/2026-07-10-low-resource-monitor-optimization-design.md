# 活跃文件夹低资源优化设计

## 目标

在保留现有 USN Journal 监听架构和紧凑交互方式的前提下，降低连续保存、大量复制和构建输出时的 CPU、内存及 GDI 资源占用，并提高长期后台运行的可靠性。

成功标准：

- 不扫描硬盘目录，只消费文件系统日志。
- 快速连续写入时，主窗口保持可点击和可拖动。
- 删除文件不显示，也不改变活跃文件夹排序。
- 活跃文件夹仍最多显示 6 个，每个文件夹仍最多展开 3 个最新文件。
- 已选择的监视范围和排除项继续跨启动保存，启动后自动监视。

## 监听层

每个支持的卷继续只启动一个 `UsnJournalVolumeWatcher`。USN 读取只请求新建、数据覆盖、数据扩展、数据截断和新名称等与产品目标有关的原因；删除事件不进入后续流程。监听优先按文件关闭边界汇总写入原因，避免一次保存被拆成大量中间事件。

路径解析支持 USN V2 的 64 位文件引用编号和 V3 的 128 位文件引用编号。无法解析的记录版本不会伪装成正常运行：每个卷、每种版本只报告一次状态提示，避免错误消息刷屏。

应用只查询已有 USN Journal，不再自动创建或调整磁盘日志。启动卷监听前检查文件系统能力；不支持 USN 或无权访问时跳过该卷，并向界面返回明确原因。

为了降低 `OpenFileById` 调用数量，监听器缓存父目录文件编号到路径的映射。缓存设容量和过期时间，命中时直接组合文件名；失效或重命名后回退到系统路径解析，确保正确性优先。

## 事件缓冲

后台线程不再向无界队列逐条追加记录。新增有界事件缓冲器，以规范化文件路径为键，只保留同一文件的最新记录。

缓冲区达到容量时，淘汰时间最早的记录。UI 每秒提取一次快照，并设置单批上限；保留最新记录后按时间顺序应用，使最终文件夹排序稳定。重新配置、清空活动或停止监视时清空旧缓冲，避免旧监视范围的事件延迟出现。

服务层保留短时间近重复抑制，但清理不再依赖字典先增长到较大规模；使用容量和时间双重边界限制内存。

## 界面更新

主窗口不再使用 `Controls.Clear()` 重建全部内容。它维护文件夹路径到 `FolderCard` 的映射：

- 新文件夹只创建一张卡片。
- 已存在文件夹只更新文字、时间、排序和三个文件行。
- 被第七个活跃文件夹覆盖的卡片从界面移除并立即 `Dispose()`。
- 排序变化只调整控件顺序，不重新创建字体、菜单和图标控件。

`FolderCard` 内预建三行文件控件，并提供 `UpdateActivity` 更新数据。字体和菜单跟随卡片生命周期统一释放。没有新事件时，定时器只刷新相对时间，不重建布局。

图标继续按扩展名缓存。缓存由应用统一拥有，卡片不释放共享图片；应用退出时统一释放缓存位图。

## 配置可靠性

配置保存先写入同目录临时文件，验证序列化结果后原子替换正式文件，并保留最近一次备份。首次保存时使用原子移动。

加载正式配置失败时尝试备份；两者都失败则使用默认配置，同时向主窗口返回可见提示。配置错误不会阻止程序启动。

## 错误与生命周期

后台错误回到 UI 前检查窗口句柄和释放状态。停止监听时先停止 UI 刷新、取消卷任务、等待任务退出，再释放卷句柄。设置变化后重新启动监听时清除旧缓冲。

每个卷的重复错误和不支持版本提示需要限频，避免错误状态自身造成刷新压力。

## 验证

扩展现有无外部依赖的烟雾测试，覆盖：

- 新建文件能够出现。
- 间隔后的独立更新能够出现。
- 删除文件完全不发布。
- 排除目录不发布。
- 大量连续写入被合并，记录数量保持有界。
- 停止和重新启动后没有旧记录混入。
- 配置写入、备份恢复和损坏回退。

另外执行 Release 构建、烟雾测试和高频文件写入压力验证。压力验证观察事件数、缓冲区上限、窗口响应以及进程 GDI 对象数量是否持续增长。

## 边界

本轮不重做视觉风格，不增加历史数据库，不扫描已有文件，不恢复删除记录，不引入后台服务或第三方依赖。现有快捷打开文件夹、打开文件、排除目录、自动启动监听和最多 6 个活跃文件夹的行为保持不变。

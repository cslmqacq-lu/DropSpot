# DropSpot 稳定启动项设计

## 问题

程序每次运行都会把当前进程路径写入 Windows 启动项。开发调试时，这会把正式安装路径覆盖成 `bin\Debug` 或 `bin\Release` 下的未签名 EXE，导致登录后出现 Windows 安全警告。

## 方案

- 正式安装版和便携版仍可把自身路径注册为启动项。
- 开发目录中的程序不得覆盖有效的非开发启动路径。
- 开发版运行时优先保留已有且存在的正式路径，其次使用 `%LocalAppData%\Programs\DropSpot\DropSpot.exe`。
- 如果没有任何稳定路径，则删除开发启动项，避免登录时继续运行调试文件。
- 仅在目标命令发生变化时写注册表。

## 验证

- 单元级 Smoke Test 覆盖开发路径识别、正式路径保留和标准安装目录回退。
- 安装 `v1.0.2` 后验证注册表指向正式安装目录。
- 重启调试版后再次验证注册表没有被覆盖。
